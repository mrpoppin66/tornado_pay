# TornadoPay V16

Telegram-бот маркетплейса услуг с PostgreSQL и деплоем на Railway.

## В этой версии
- новый сценарий создания заявки: услуга → сумма → реквизиты → подтверждение → публикация исполнителям;
- заявка не создаётся и средства не резервируются до подтверждения реквизитов клиентом;
- четыре услуги: Пополнение мобильного, Перевод на карту, Перевод по СБП, Оплата по QR;
- для Пополнения мобильного и Перевода по СБП запрашивается номер телефона; для Перевода на карту — номер карты; для Оплаты по QR — ссылка на QR/СБП или фотография QR-кода;
- реквизиты скрыты от исполнителей до момента взятия заявки; после взятия отображаются в активной заявке; QR-фото автоматически отправляется исполнителю;
- клиент подтверждает введённые реквизиты отдельным экраном перед созданием заявки;
- пользовательский кабинет и история заявок;
- кабинет исполнителя: доступность, свободные заявки, активная заявка, история, баланс, вывод;
- единый жизненный цикл заявки: новая → в работе → на подтверждении → выполнена / спор / отменена;
- анонимный чат клиент ↔ исполнитель внутри бота;
- непрочитанные сообщения и последние текстовые сообщения при открытии чата;
- поддержка текста, фото, видео, документов и других Telegram-сообщений через копирование ботом;
- уведомления клиенту/исполнителю о ключевых событиях заявки;
- админские вкладки по статусам заявок;
- раздел споров с просмотром последних сообщений и решением в пользу клиента или исполнителя;
- статистика исполнителя и рейтинг;
- каталог услуг и админское управление комиссиями;
- комиссии не показываются клиенту/исполнителю, только итоговые суммы;
- вывод исполнителя пока только как внутренняя заявка на выплату; xRocket/CryptoBot подключаются отдельно;
- никаких адресов кошельков бот не запрашивает.

## Данные
При старте нет DROP TABLE. Миграции добавляют только недостающие структуры. Существующую PostgreSQL-базу не удалять.

## Railway
Переменные: `BOT_TOKEN`, `DATABASE_URL`, `ADMIN_ID`.

## V17 — «Карта под оплату»

Добавлена услуга `💳 Карта под оплату`.

Сценарий:
1. Клиент выбирает услугу и вводит сумму.
2. Заявка создаётся сразу и становится доступна исполнителям.
3. Исполнитель берёт заявку.
4. Исполнитель указывает безопасную метку используемой карты (банк + последние 4 цифры).
5. Открывается анонимный чат для дальнейшей координации.
6. Исполнитель отмечает выполнение, клиент подтверждает или открывает спор.

В боте намеренно не предусмотрен ввод/хранение полного номера карты, CVV/CVC, срока действия или SMS/OTP-кодов.


### V18 — зашифрованные данные карты исполнителя
Для услуги «💳 Карта под оплату» бот запрашивает у исполнителя номер карты, срок действия и имя держателя. Полные данные шифруются Fernet до записи в PostgreSQL; в открытом виде хранится только метка `Карта •••• 1234`. CVV/CVC и SMS/OTP-коды бот не запрашивает и не сохраняет.

Добавьте в окружение переменную `CARD_DATA_ENCRYPTION_KEY`. Ключ можно сгенерировать командой: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`. Храните ключ отдельно от БД и не меняйте его без миграции/расшифровки старых записей.
