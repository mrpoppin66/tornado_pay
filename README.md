# TornadoPay v21

Обновление: для услуги **«Карта под оплату»** бот больше не запрашивает и не сохраняет данные карты исполнителя.

Сценарий:
1. Пользователь выбирает «Карта под оплату».
2. Вводит сумму.
3. Вводит комментарий, что оплачивается.
4. Заявка создаётся и становится доступной исполнителям.
5. Исполнитель берёт заявку.
6. Бот сообщает исполнителю, что данные карты нужно отправить пользователю через анонимный чат.
7. Пользователь и исполнитель общаются через чат.
8. Исполнитель отмечает выполнение, пользователь подтверждает.

Старые поля `executor_card_reference` и `executor_card_encrypted` в БД намеренно не удаляются для совместимости со старыми версиями. Новая версия их не заполняет.

Для остальных услуг сценарий не изменён.

## Обязательная подписка на канал

Чтобы включить проверку подписки на новостной канал перед началом работы с ботом:

1. Добавьте бота **администратором** в нужный канал (без этого Telegram не даст боту проверять подписчиков, особенно у приватных каналов).
2. Узнайте числовой ID канала — перешлите любое сообщение из канала боту `@userinfobot` (или `@getmyid_bot`), он пришлёт что-то вроде `-1001234567890`.
3. Добавьте в переменные окружения (Railway → Variables):
   - `REQUIRED_CHANNEL_ID` — числовой ID канала (например, `-1001234567890`) или его username (например, `@tornadopay_news`).
   - `REQUIRED_CHANNEL_URL` — ссылка на канал для кнопки «Перейти в канал» (например, `https://t.me/tornadopay_news`, для приватного канала — ссылка-приглашение).

Если `REQUIRED_CHANNEL_ID` не задан — проверка подписки отключена, бот работает как раньше.

Порядок для пользователя: принять пользовательское соглашение → подписаться на канал → бот открывает главное меню. Оба условия проверяются при каждом действии в боте (не только при `/start`), так что подписку нельзя обойти, просто закрыв сообщение с просьбой подписаться.

Если бот не сможет проверить подписку (например, забыли добавить его администратором в канал), пользователей это не заблокирует — проверка в этом случае пропускается, а ошибка попадает в лог сервера, чтобы её можно было заметить и поправить конфигурацию.

## xRocket Pay API (Current)
Use the current Pay API token, not a Legacy `Rocket-Pay-Key`:
```env
XROCKET_API_TOKEN=your_current_pay_api_bearer_token
XROCKET_WEBHOOK_SECRET=your_pay_api_webhook_secret
XROCKET_BASE_URL=https://pay.api.xrocket.exchange
```
In @xRocket open your application → Settings → API Version → Current, then issue/copy the API Token. Do not use an Exchange API token here.

## Telegram Mini App

Рядом с обычным чат-ботом теперь работает Mini App — тот же функционал (услуги,
заявки, чат, баланс, пополнение/вывод, рефералка, кабинет исполнителя), но в
виде веб-интерфейса внутри Telegram. Пользователь сам решает, чем пользоваться
— обе версии работают с одной и той же базой данных и бизнес-логикой в
реальном времени.

Технически это статический фронтенд (`app/webapp_static/`, без сборки) и
REST API (`app/webapp_api.py`), встроенные в тот же веб-сервер, что уже
принимает вебхук xRocket (`app/bot.py: start_web_server`). Отдельный сервис
на Railway заводить не нужно — открой Mini App по адресу `/webapp/` на том
же домене, где развёрнут бот.

Чтобы кнопка «Открыть в приложении» и кнопка меню бота заработали, задай в
переменных окружения:

```env
PUBLIC_BASE_URL=https://<твой-домен-на-railway>
```

Без этой переменной сам Mini App всё равно доступен (по прямой ссылке
`https://<домен>/webapp/`), но бот не сможет автоматически показать кнопку
для его открытия.

Аутентификация в API — через `Telegram.WebApp.initData`, с проверкой HMAC-подписи
на бэкенде (`app/webapp_auth.py`) по официальному алгоритму Telegram; отдельный
логин/пароль не нужен, доступ есть только у пользователя, открывшего Mini App
через своего Telegram-бота.

Админ-панель в Mini App сознательно не вынесена — она осталась только в боте.
